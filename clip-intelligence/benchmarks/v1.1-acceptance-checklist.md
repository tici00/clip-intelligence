# v1.1 Acceptance Checklist

Use this checklist before treating the Skill changes as validated or submitting the corresponding Capafy Agent version.

## Output usefulness
- [ ] Default output returns up to five strong primary recommendations, not weak filler.
- [ ] If fewer strong moments exist, the output returns fewer and explains why.
- [ ] Alternatives are separate from primary recommendations and are not duplicates.
- [ ] Every primary recommendation has a Creator-Ready Clip Package.
- [ ] Editorial suggestions are not presented as direct quotes.
- [ ] Platform-specific caption/hashtag rules are applied only when platform context is known.

## Goal modes
- [ ] Balanced Discovery is used when the user gives no goal.
- [ ] Growth, Community, Personality/Connection, and Evergreen/Value alter relevance and ranking transparently.
- [ ] No mode forces equal type distribution or inflates scores.
- [ ] Selected mode is stated in Source & Scope.

## Evidence and boundaries
- [ ] Every primary candidate includes start/end reasoning.
- [ ] Alternate boundaries state the trade-off.
- [ ] Standalone Clarity is rated and consistent with Required Context.
- [ ] Visual claims distinguish observed video from transcript/audio, inference, and unverified claims.
- [ ] Transcript-only analysis marks visual potential as evidence-limited.
- [ ] NO-CLIP summary is concise and representative, unless a full audit is requested.

## Score transparency
- [ ] Scores are described as structured judgments, not probabilities or virality predictions.
- [ ] No precise visual score is invented from transcript-only evidence.
- [ ] No statistical performance claim is made without a measured evaluation.

## Cost controls
- [ ] Existing valid transcript/evidence is reused where possible.
- [ ] Full packaging is generated only for primary candidates.
- [ ] Candidate chunks preserve original source offsets.
- [ ] Cost/runtime measurements are recorded when available.
- [ ] No unmeasured savings or hard limits are promised.

## Automatic Video Intake readiness
- [ ] A supported upload or direct media URL is accessible in the runtime.
- [ ] Source access is verified before processing.
- [ ] Audio extraction is performed by an actual supported tool/service.
- [ ] Timestamped transcription is actually produced and validated.
- [ ] Chunk offsets and boundary overlaps are handled correctly.
- [ ] The resulting transcript is passed to the normal opportunity-discovery workflow.
- [ ] Visual analysis is claimed only if video/frame evidence was actually inspected.
- [ ] Private/inaccessible URLs fail clearly without access-control bypass.
- [ ] Full-duration coverage, failures, and evidence limitations are reported.
- [ ] Cost, processing time, retries, file size, and duration limits are tested.
- [ ] Marketplace copy claims link-to-clips only after the above tests pass.
